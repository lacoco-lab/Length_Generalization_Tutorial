# C-RASP and transformer length generalization

An editable, interactive companion to the C-RASP tutorial. Open `site/index.html` through a local web server; all deployable files are in `site/`.

## Preview and edit

```sh
python3 -m http.server 8000 --directory site
```

Visit http://localhost:8000 for the main tutorial, or http://localhost:8000/version2/ for the separately developed experimental version. Run the server from the repository root. `npm run preview` starts the same server. Edit article prose in `site/index.html`, styling in `site/assets/style.css`, and article interactions in `site/assets/article.js`. This first edition uses semantic HTML, CSS and JavaScript with no build step or Node dependencies. It can live in a GitHub Pages project subdirectory or on the chair's web server. The paper's Typst source remains separate; this is an editorial adaptation, not an automatically synchronized export.

The page has visible formal explanations, anchored sections, keyboard-accessible trace inspection, editable examples, program-sharing URLs, trace downloads, attention and positional-relation illustrations, published figures, and a saved-evaluation gallery. It is responsive and has a print stylesheet.

## Integrated article

The main `index.html` draft embeds two independent activities in the reading sequence: a Dyck-1 walkthrough and a general block playground. The latter starts with “contains a” and offers programs for both-symbol presence and a-before-b order. It also supports starting empty. Both activities run locally without a Python download. The article proceeds from those examples to attention constructions, positional information, idealized length generalization, empirical evidence, and limitations.

The embedded views reuse `notebook.html?embed=walk` and `notebook.html?embed=build`. Their same-origin resize messages let the article display each activity at its full height, including after edits. `article.js` handles the article widgets; `editor.js` handles the separate optional text editor. Older shared-program links to `index.html#program=…` redirect to that editor.

## The optional text editor and Python implementation

The separate `text-editor.html` page runs the original **interpreter** from [coli-saar/c-rasp, c-star-rasp](https://github.com/coli-saar/c-rasp/tree/c-star-rasp), commit `1e821d7279015ce0e77830faa7932575447c5164`. It does not compile transformer weights or train a model. It uses ordinary C-RASP execution, not the optional C*-RASP mode. Upstream source is fetched by immutable commit at runtime rather than copied into this repository. The manifest is `site/data/interpreter.json`.

Python runs in a disposable Web Worker with Pyodide 0.27.7 and antlr4-python3-runtime 4.13.1. The first Run needs internet access to jsDelivr, PyPI and raw.githubusercontent.com and can take several seconds. Program/input contents stay in the browser; only dependency downloads are sent to those hosts. Sharing a link deliberately embeds the program and input in its URL fragment. No program auto-runs from a shared link. The initial example trace was generated by the pinned interpreter and works without loading Python.

The UI limits execution to 128 tokens and 64 assignments and stops the worker after 90 seconds. Positions are zero-based, prefix counts inclusive, and a recognition program must end in a Boolean vector. The last position determines the interpreter result. This is an implementation convention, not a claimed treatment of the empty word in the papers.

## Saved experiments

Published figures 1 and 2 from Huang et al. are included unchanged, with URLs, license attribution, retrieval dates and SHA-256 checksums in `site/data/figure-provenance.json`.

`site/data/evaluations.json` intentionally starts empty. Add real saved evaluations there, or use the browser's local JSON importer. The schema is `site/data/evaluation-schema.json`. Each run records its task, model, positional encoding, seed, checkpoint, evaluation timestamp, source, training-length maximum, and optional maximum length used for model selection. Each point stores `length`, `correct`, and `total`; accuracy is derived from those counts. The only supported metric is whole-sequence accuracy. Missing evaluations must be omitted, never filled with zero. Curves are displayed individually without aggregating seeds or mixing checkpoints. Lines between measured points are visual guides, not additional measurements.

Importing does not upload files or start experiments. Do not include unpublished or private data in the tracked JSON unless intended for the site's audience.

## Five notebook experiments

Visit `notebook.html` to compare five alternative learning interfaces:

1. **Walkthrough:** reveals one assignment at a time and highlights contributing prefix tokens.
2. **Block builder:** drag or click typed operations, select compatible earlier variables, and read vectors directly on each block. Invalid reorderings and removal of dependencies are rejected. Arrow buttons provide a keyboard/touch alternative to dragging.
3. **Repair a rule:** change a comparison and a Boolean connective, using counterexamples to understand the two conditions for balanced parentheses.
4. **Token sandbox:** flip, add, or remove symbols and inspect the changes in counts, the first invalid prefix, and the final decision.
5. **Predict a value:** predict a selected cell, then reveal it with an explanation.

These are comparative prototypes, not a required five-step course. The original text editor remains available. For a novice-facing version, a promising sequence is the walkthrough followed by the block builder; that is a design hypothesis, not a tested learning outcome.

The new page uses a synchronous JavaScript evaluator over a typed block representation. It needs no Python download or network access after the static assets load. Source generation is separate from evaluation, and the page can transfer a program into the original Python-backed text editor. The builder is limited to 24 blocks and 16 nonempty input positions; it is deliberately a subset of C-RASP. Unselected output is an execution sentinel and is never shown as an acceptance decision.

Source layout:

- `site/assets/notebook-model.js`: types, templates, validation, and code generation.
- `site/assets/notebook-engine.js`: pure block evaluation, with checked integer arithmetic.
- `site/assets/notebook.js`: the five interfaces and explanatory feedback.
- `site/assets/notebook.css`: layout for the notebook experiments.

`node --test tests/*.test.mjs` checks types, dependency ordering, and causal counting. For a differential check of complete JavaScript and Python traces, use an environment with `antlr4-python3-runtime==4.13.1` and the pinned interpreter checkout:

```sh
.venv/bin/python scripts/check_notebook_interpreter.py /path/to/c-rasp /path/to/node
```

This checks 443 traces, including deterministic random programs and every nonempty parenthesis input through length 7. It does not prove correctness of arbitrary programs.
