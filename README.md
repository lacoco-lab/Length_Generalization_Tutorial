# C-RASP and transformer length generalization

An editable, interactive companion to the C-RASP tutorial. Open `site/index.html` through a local web server; all deployable files are in `site/`.

## Preview and edit

From the repository root:

```sh
python3 -m http.server 8000 --directory site
```

Then open:

| Edition | URL |
|--------|-----|
| **Main tutorial** (original) | http://localhost:8000/ |
| **Version 2** (experimental) | http://localhost:8000/version2/ |

Or use the npm script: `npm run preview` (same server).

Edit the main tutorial in `site/index.html`, `site/assets/style.css`, and `site/assets/app.js`. This first edition uses semantic HTML, CSS and JavaScript with no build step or Node dependencies. It can live in a GitHub Pages project subdirectory or on the chair's web server. The paper's Typst source remains separate; this is an editorial adaptation, not an automatically synchronized export.

### Version 2 (experimental, separate)

A second edition lives in **`site/version2/`**. It has a leaner chapter structure and drag-and-drop C-RASP program editing. It does **not** replace the main tutorial.

- Start the server as above, then visit http://localhost:8000/version2/
- From the main page: use the **Version 2** link in the header/footer
- Files are self-contained under `site/version2/` (`index.html`, `assets/`, `runtime/`, `data/interpreter.json`), so edits there cannot overwrite the main `site/` tutorial

The page has visible formal explanations, anchored sections, keyboard-accessible trace inspection, editable examples, program-sharing URLs, trace downloads, attention and positional-relation illustrations, published figures, and a saved-evaluation gallery. It is responsive and has a print stylesheet.

## The existing Python implementation

The playground runs the original **interpreter** from [coli-saar/c-rasp, c-star-rasp](https://github.com/coli-saar/c-rasp/tree/c-star-rasp), commit `1e821d7279015ce0e77830faa7932575447c5164`. It does not compile transformer weights or train a model. It uses ordinary C-RASP execution, not the optional C*-RASP mode. Upstream source is fetched by immutable commit at runtime rather than copied into this repository. The manifest is `site/data/interpreter.json`.

Python runs in a disposable Web Worker with Pyodide 0.27.7 and antlr4-python3-runtime 4.13.1. The first Run needs internet access to jsDelivr, PyPI and raw.githubusercontent.com and can take several seconds. Program/input contents stay in the browser; only dependency downloads are sent to those hosts. Sharing a link deliberately embeds the program and input in its URL fragment. No program auto-runs from a shared link. The initial example trace was generated by the pinned interpreter and works without loading Python.

The UI limits execution to 128 tokens and 64 assignments and stops the worker after 90 seconds. Positions are zero-based, prefix counts inclusive, and a recognition program must end in a Boolean vector. The last position determines the interpreter result. This is an implementation convention, not a claimed treatment of the empty word in the papers.

## Saved experiments

Published figures 1 and 2 from Huang et al. are included unchanged, with URLs, license attribution, retrieval dates and SHA-256 checksums in `site/data/figure-provenance.json`.

`site/data/evaluations.json` intentionally starts empty. Add real saved evaluations there, or use the browser's local JSON importer. The schema is `site/data/evaluation-schema.json`. Each run records its task, model, positional encoding, seed, checkpoint, evaluation timestamp, source, training-length maximum, and optional maximum length used for model selection. Each point stores `length`, `correct`, and `total`; accuracy is derived from those counts. The only supported metric is whole-sequence accuracy. Missing evaluations must be omitted, never filled with zero. Curves are displayed individually without aggregating seeds or mixing checkpoints. Lines between measured points are visual guides, not additional measurements.

Importing does not upload files or start experiments. Do not include unpublished or private data in the tracked JSON unless intended for the site's audience.

## Checks

Node 20 or newer, no npm install:

```sh
node scripts/check.mjs
node --test tests/*.test.mjs
```

The checks validate local assets and anchors, figure checksums, data integrity, and rejection of missing/inconsistent evaluation counts. To validate the actual interpreter adapter against all 254 nonempty parenthesis strings through length 7:

```sh
python3 -m venv .venv
.venv/bin/pip install antlr4-python3-runtime==4.13.1
# Supply a local checkout of coli-saar/c-rasp at the pinned commit:
.venv/bin/python scripts/check_interpreter.py /path/to/c-rasp
```

## Hosting

For GitHub Pages, push this repository to the chosen destination, choose **Settings → Pages → Source → GitHub Actions**, then manually run **Publish tutorial to Pages**. Deployment is deliberately manual while the article is a working draft. The separate check workflow runs on pushes and pull requests. No hosting has been activated by preparing these files.

For the chair's website, copy the contents of `site/` into the desired directory. Relative asset paths support subdirectory hosting. Serve `.js` with a JavaScript MIME type and `.svg` as `image/svg+xml`. The host's content-security policy must permit the worker and Pyodide's WebAssembly/runtime dependencies; test the playground after deployment. The article and saved figures do not need a backend.
