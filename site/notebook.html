See a program take shape.

You do not need to know the syntax. A C-RASP program assigns a value to every token position. Some values are numbers; others are yes/no answers. Try five ways of working with those values below.

Start with the walkthrough, or try the block builder to construct a program. These are alternative notebook designs for comparison, not five required lessons.

What each design lets us test

01 · Walkthrough
Does revealing one assignment at a time make a vector computation easier to follow?
02 · Block builder
Can readers construct and modify well-formed programs by connecting typed operations?
03 · Repair a rule
Does a small counterexample explain why comparing final counts is insufficient?
04 · Token sandbox
Do immediate changes in prefix counts help connect a symbol sequence to its computation?
05 · Predict a value
Can readers infer a cell before seeing it, and explain their prediction?

These activities evaluate structured blocks directly in your browser, without a download or server-side execution. The evaluator is cross-checked against the original C-RASP Python interpreter during development. This is a small typed subset, not all of C-RASP. It prevents malformed expressions and forward references; a well-formed program can still compute the wrong function. No transformer is trained here.

Position labels start at 0. Prefix counts include the current position. The learning examples use nonempty inputs of at most 16 tokens; empty-word recognition is outside these activities. Yes/no values are displayed as words rather than unexplained symbols.
